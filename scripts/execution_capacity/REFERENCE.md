# Linux reference single-round coordinator

`ReferenceAttempt` connects one physical round to actual source/control authority. It is not a full benchmark driver or completed capacity acceptance. Import and `calibration.py --help` do not initialize resources. Source sealing, diagnostics, cumulative cleanup predicates and private replay/copy are implemented helper paths; complete native scheduling/collection and their multi-round runtime integration remain required. Reviewed command fences, physical ownership corrections and original receipt anchors remain enforced.

The current `reference_round.reserve_round` rejects every second physical round with `prior physical round retained; C2c cleanup/reuse gate not implemented`. The normal acceptance CLI does not construct the mandatory `OfflineProofContext` described below. Neither helper tests nor a public report establish a full AC21 pass; see [current acceptance status](../../e2e/README.md#ac21-capacity-prerequisite-and-current-status).

## Provisioned backend prerequisites

The implemented backend is same-host Linux x86_64 with usable KVM API 12, a fixed `/usr/bin/qemu-system-x86_64`, `/usr/bin/qemu-img`, `/usr/bin/taskset`, `/usr/bin/python3`, `/usr/bin/findmnt`, `/usr/sbin/ip`, `/usr/sbin/tc`, and `/usr/sbin/ethtool`. Required privileges/delegation must already exist. No installer, sudo fallback, TCG fallback, global forwarding, NAT, default client route or physical-interface changes are provided.

This backend supports directly resolved host PCI NVMe (non-virtual/non-stacked sysfs block mapping) on ext4/XFS. The file device is matched against findmnt and the host sysfs block device/controller model/serial/firmware, then actual QEMU backing/overlay descriptors must show O_DIRECT. Other SSDs can satisfy the specification but this backend does not yet implement their hardware corroboration. Device caches are uncontrolled. No guest virtio rotational flag substitutes for host storage evidence.

The operator must delegate two distinct, empty sibling cgroup-v2 leaves, with exact device/inode identities and already-isolated cpuset partitions. The server uses 16 specified CPUs on 16 distinct physical cores; the client uses at least four CPUs on at least four other physical cores. At least one further physical core remains for host work. The immutable plan declares positive QEMU memory overhead and host memory headroom. Actual host MemTotal and MemAvailable must cover 32 GiB + server overhead + 16 GiB client + host headroom. The code records hardware topology and DMI; those are observations, not a hardware authenticity attestation.

`ResourceAllocation.configure()` writes only those leaves: server memory.max/min = 32 GiB + declared QEMU overhead, client memory.max/min = 16 GiB, memory.swap.max = 0, cpu.max = max. It checks effective cpus, ancestor quotas/limits and combined parent memory protection/capacity. Actual pressure, CPU statistics, memory usage/events, process membership, per-thread affinity and I/O remain distinct from configuration. This allocation does not certify absence of all host contention; C2b3/C3 must sample and report the actual running intervals.

## Private immutable host plan additions

- `network`: `{"attempt_id": "<UUID>", "subnet": "<unused private IPv4 /30>"}`. Namespace and link names/aliases derive from the UUID. Both directions share one physical link for all ten contexts, with 25 ms and 20 Mbit/s on each egress (nominal decimal 2,500,000 bytes/s), limit 1000.
- `resources`: `topology="same-host-linux-x86-kvm"`; positive integer `qemu_overhead_bytes` and `host_headroom_bytes`; `groups.server` and `groups.client` each contain exact absolute `path`, `identity={device,inode}`, and CPU-ID list `cpus`.
- `calibration`: SHA256 strings `service_sha256`, `infrastructure_sha256`, `host_python_sha256`; `host_key_path` names a private 0600 single-link regular file containing exactly 32 random bytes; `phases` preregisters a subset of `baseline/pre/window/post`; `validity` contains positive integer `added_rtt_min_ns`, `added_rtt_max_ns`, `throughput_min_bps`, `throughput_max_bps`. These are explicitly declared measurement validity bounds, not specification-provided numbers or modified UI latency budgets. Missing measurements never pass.

Key bytes never enter argv, host ledger, QGA payloads, returned results or public reports. The host passes the key only through the exact owned calibration child's stdin after process/resource/network registration. All operational records are private; C2b3 must map approved safe fields to the single report authority.

## Callable order and ownership

1. Create one `OwnedNetwork(plan, ledger)` and call `create()`; successful create records actual namespace inode and holds its descriptor, both ifindices/peer aliases/addresses, connected routes, baseline noqueue and offload readbacks. Lost create is consumed. Missing identity means retain for operator reconciliation; names alone never authorize retry or deletion.
2. Call `ResourceAllocation(ledger).configure()`. Before launching QEMU, reserve `network.reserve_consumer("qemu:" + vm.plan.uuid, client=False)`. The C2b3 VM owner creates/launches the VM, authenticates QMP and calls its existing `verify_paused()`. Then `resources.bind_vm(vm, network)` requires that actual paused record and no prior cont intent, rereads exact process identity, binds the server envelope, records physical storage/O_DIRECT, and registers QEMU's pidfd as a network consumer. QMP cont/guest boot/socket recovery belong to the VM owner.
3. On an authenticated `GuestSession`, `infrastructure("resources")` re-inspects actual containers, reads guest CPU/memory and the exact PG process cgroup. Docker's configured PG memory alone is insufficient: current leaf/ancestor limit must actually be 8 GiB, swap zero, and the running PG init PID must be a cgroup member. Guest MemTotal is preserved as the OS sees it; it is not relabelled 32 GiB. QMP's independent actual memory-size readback supplies the guest RAM allocation.
4. `session.infrastructure("start")` consumes a single fixed service start. `observe` reports actual MainPID/start ticks/argv/executable/cgroup, boot, listener FD/socket inode and resource usage. `stop` requires the originally observed exact service identity, pidfd exit and inactive/unpopulated readbacks. A replacement process cannot be stopped using the earlier identity. Lost responses retain uncertainty; do not retry start/stop.
5. `Calibration(vm, session, network, resources).run("baseline")` observes native echo RTT and bounded streams before shaping. Then `network.shape()` applies/reads both egress netem qdiscs. `run("pre")`, `run("window")`, `run("post")` are separately consumed phases as preregistered. Each client is a separately launched fixed process in the owned namespace, bound to the client allocation and registered before the secret/start payload is delivered. The control lock is released only for this independently tracked long host client. Every QGA infrastructure call still uses the serialized GuestSession command path.
6. Each calibration phase makes 16 authenticated echo probes and one 8 MiB upload and download. An echo RTT is the actual echo send-to-receive interval after authentication; connection/authentication overhead and full probe intervals remain recorded. Throughput uses actual complete bytes divided by actual elapsed time, including protocol overhead. Each probe has a 15 s absolute I/O deadline, connection timeout 5 s, overall host child limit 120 s. No retries. Raw TCP delivery cannot measure packet loss; `packet_loss=null` is explicit, while actual qdisc packet/byte/drop deltas are retained. Before/after service CPU/memory readings include its cost. Calibration never requests product/API data or warms a cold product target.
7. Register every future native/admission child using a unique pre-effect consumer reservation and exact process identity; the C3 collector must ensure all ten contexts share this namespace. `cleanup()` requires every reservation to be registered, every retained pidfd to report exit, no remaining namespace processes, and unchanged namespace/veth identities before deleting only the owned veth/netns. The QEMU consumer must also exit, which removes its hostfwd and guest service. Guest service stop precedes VM termination in the future coordinator. Uncertain/partial cleanup and reopened ledgers without live pidfd authority remain retained; no guessed cleanup/export exists.

Every probe has its own actual monotonic interval and byte count. Pre/window/post records do not claim continuous transfer throughout a source window. Under-load RTT can include real queueing. C2b3 must reconcile the current shared calibration schema accordingly, and actual operational overhead/validity need later reference-machine measurement.

Reopening on another clock domain rejects continuation; legacy timestamp journals without an observed domain cannot acquire a fabricated old epoch. The VM process identity now uses the same actual `/proc/PID/exe` descriptor observation as the guest bridge and hashes raw NUL-delimited argv bytes. Its cgroup changes during `ResourceAllocation.bind_vm`; `accept_resource_transition` retains and verifies that actual transition.

`GuestSession.source_shards(kind)` uses fixed RESULT requests with `kind` in `metadata/snapshots/ticks/progress` and a nonnegative page index, only after the original START exit is observed. Each guest page contains at most 16 typed rows, at most 512 KiB of row bytes, total/count/index and a digest; the host checks exact boot/window/kind, counts and hashes. The 10,000-row per-kind per-window bound fails without truncation. Source metadata retains `pending_C`. These shards supply actual source facts to a future Workload assembler; they are not native paint, a complete report, a clean seal or cleanup proof.

Calibration export retains each fixed echo/upload/download interval and its bytes, elapsed time and phase. Transfers are the actual fixed 8 MiB in each direction; no pre/post pair is turned into continuous coverage. Full window probes must fit inside the immutable covered window. Echo RTT alone excludes connection/authentication overhead, while the full probe interval includes it. A synthetic 30-second window does not prove runtime feasibility. The later coordinator must preregister the complete schedule and reject infeasible or late calibration without extending source duration.

The 32 GiB package limit is a disk I/O guard; individual artifacts remain limited to 32 MiB, with 2,048 artifacts maximum. It is neither a 16 GiB client memory guarantee nor a proved final cumulative-inventory bound. Current `load_artifacts` retains raw bytes and merges all parsed objects, so the queued bounded-consumer work is mandatory before a runnable native driver. C2c must recalculate package/report size after actual cumulative batch/lease/upload/broker inventories exist, keeping all identities in typed artifacts rather than duplicating millions of IDs into the 256 MiB summary report.

## Physical review FIX1 contract

The supported iproute2 v6.8.0 netem JSON shape explicitly includes `ecn: false` and `gap: 0`, in addition to the fixed delay/rate/limit objects. Unknown options, non-neutral values and wrong JSON boolean/integer types are rejected rather than discarded.

Consumer reservation, registration and the complete teardown sequence share the ledger's control lock. A reservation with no registered exit authority (including a not-yet-spawned child) prevents starting teardown. After all reserved consumers have observed exits, `network-teardown-intent` durably records that exact reservation/consumer set before namespace emptiness checks or deletion. The lock stays held through the final outcome. New reservations/registrations and other network mutations then fail, including after reopen, successful release, lost deletion response or readback failure. Old deletion-intent/released records also close the fence. A teardown failure records retained error state; no deletion retry or reconstructed pidfd authority is provided here.

Calibration stop now signals only the reauthenticated retained pidfd with SIGTERM and waits at most five seconds for that exact process's POLLIN exit observation. There is no `systemctl stop`, cgroup kill, numeric-PID signal or replacement-process fallback. Systemd is subsequently queried read-only for inactive/MainPID-zero status, with unchanged `ExecMainPID` and `ExecMainStartTimestampMonotonic`; the owned cgroup must be absent or unpopulated. These properties are raw execution-generation corroboration, never clock conversion or independent termination authority. Even a replacement that has already exited changes the generation and invalidates the stop receipt. Missing properties, signal errors, timeout, replacement or uncertain quiescence remain retained. GuestSession's preregistered command deadline still applies and must cover the actual helper operation; no control deadline is silently extended.
