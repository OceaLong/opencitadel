# Controlled evaluation environments

E04 environments are registered test inventory. An ordinary suite/configuration cannot turn an existing connector into a test connector. Registry registration and repair require a currently authorized administrator in the same workspace; administrators receive no additional business-body read permission.

## Local Docker capability

The included `docker-http-cell-v1` adapter owns a fresh sandbox, HTTP fixture, proxy and isolated networks for every lease. It is deliberately available only when `EVALUATION_LOCAL_DOCKER_ENABLED=true`, `EVALUATION_TEST_INVENTORY_PATH` names an administrator-controlled JSON file, and `ENV` is not `production`. Default deployments expose no available environment adapters. These are restart-bound deployment settings, never HTTP fields.

`deploy/evaluation/local-fixture.example.json` documents the closed inventory schema and observed local image content identities. Those IDs are local cache identities, **not registry manifest digests** and not a portable registry reference. Verify the selected immutable caches on the controller before enabling the capability. No component pulls/builds images automatically. The fixed bootstrap image contains firewall tools; its normal kind/kubelet/containerd entrypoint is never started. It runs fixed commands with only NET_ADMIN in the fresh case network namespace and exits before any case tool can run. The case receives no such capability, host namespace/mount/socket or production secret.

The owned Docker integration tests require `E04_REAL_DOCKER=1`. Their original host-local image defaults can be overridden with `E04_TEST_FIXTURE_IMAGE`, `E04_TEST_SANDBOX_IMAGE`, and `E04_TEST_BOOTSTRAP_IMAGE`. Each value must be a full immutable local content ID (`sha256:` followed by 64 lowercase hexadecimal characters); tags and registry references are rejected. Inspect and verify the selected locally available images before running these tests. These test-only overrides do not change deployment inventory or enable production adapters, and do not pull or build missing images. The fixture must provide Python and the owned HTTP fixture runtime; the sandbox must provide the sandbox service, shell, and Chromium; the bootstrap must provide the fixed firewall tools.

The HTTP fixture origin is `http://allowed.e04.test:8081`. This logical test origin resolves through the private per-lease proxy to the corresponding owned fixture container. Shell and Chromium use the same confined network. Direct IP/port/DNS/UDP paths and unregistered proxy authorities are denied. An unavailable proxy fails closed. Arbitrary websites and arbitrary private services are outside this adapter's supported inventory.

After choosing the deployment inventory, an administrator reads
`GET /api/evaluation/environments/inventory`, then registers the exact target and
credential through `POST /api/evaluation/environments/inventory/{kind}/{identity}/register`
with `{request_id, revision}` (`kind` is `target` or `credential`). This selects
trusted records without putting credential locators/contracts in a public form.
The management alternative is POST `/api/evaluation/environments/registry` using
`{request_id, kind:"target", value:<exact inventory target>}`. The service rejects any changed endpoint, connector binding, credential binding or contract. Register an environment with kind `environment`, a new immutable UUID, `image_digest:{kind:"local_content_id",value:<sandbox sha256>}`, `fixture_revision:"empty-home-v1"`, `reset_adapter:"docker-http-cell-v1"`, `adapter_revision:"docker-http-cell-v1"`, `healthcheck_revision:"owned-absence-v1"`, and `allowed_targets:[{id:<target UUID>,revision:1}]`. Limits default to two environments per workspace and cannot exceed the trusted deployment ceiling. An environment version UUID never changes its content; create a new UUID for a new version.

The suite then selects this fixed environment version. Registry/preflight checks read scoped metadata only. The current batch scheduler calls `prepare_environment_binding` with the actual
policy pair in its trusted kernel UoW, binds the immutable budget and execution
slot, then enqueues the matching Run in that same transaction. E04 does not expose a route that directly invokes tools/providers or admits a Run.

## Controlled protocol support

The registered HTTP executor supports the owned stateless JSON-response MCP fixture with protocol `mcp-stateless-json-2025-03-26`: it initializes and negotiates that version, sends `notifications/initialized`, then invokes only the registered source tool. It performs no tool discovery. Session-bearing or streaming/SSE MCP, stdio, other negotiated protocol versions and arbitrary downstream endpoints are unavailable. A2A supports the fixed JSON-RPC `message/send` path with protocol `a2a-jsonrpc-0.3` and explicit registered agent IDs. These calls travel through the same lease-local proxy, never a global connector pool or controller-host network fallback. Redirects are denied. Full tool contracts, connector identities and binding revisions must originate in the administrator-controlled test inventory and match the current scoped connector record. Editing/revoking that record invalidates eligibility.

Synthetic fixture credentials use the registered resolver and locator `synthetic-e04-v1`, bound to the exact target revision. This resolver supplies only the code-owned synthetic test header. No arbitrary production credential import or decryption fallback is provided. Credential locators and contracts are excluded from public registry responses.

Shared physical services need an independently registered controlled reset/verify adapter. The included local adapter uses owned copies and rejects shared services. The repository's shared-resource fence spans batches, environment aliases and target aliases; physical origin registration in another workspace is refused. Dirty fences survive expiry, cancellation and cleanup failure.

## Lifecycle and recovery

Durable phases are prepare, reset, verify_ready, cleanup and verify_clean. Every callback checks operation claim generation plus lease generation/revision. `verified_clean` is the only reusable state; cancellation/expiry never implies cleanliness. Unknown in-flight prepare cancellation remains quarantined, including after cleanup/absence verification, and retains resource fences. The former exact worker can acknowledge its final physical outcome without changing the newer lease. An unresolved physical operation prevents repair release. POST `/api/evaluation/environments/leases/{lease_id}/repair` with `{request_id}` queues an explicitly authorized repair; only successful cleanup and verification can release quarantine/fences.

Cleanup enumerates the exact lease ownership label set, records concrete Docker IDs, verifies complete labels again and removes only those resources. No global prune, shared network attachment or host firewall mutation occurs. Failed cleanup remains visible through the persistent lease state and pending count. Runtime rejects a changed/restarted case or a changed physical resource set; it never substitutes a normal session sandbox.

To enable a controlled protocol fixture, replace the HTTP fixture entry in the `targets` array with a single protocol target with `kind:"mcp"`, `protocol:"mcp-stateless-json-2025-03-26"`, endpoint `http://allowed.e04.test:8081`, and the current scoped connector ID/revision. Set its `contracts` to the fixed full `RecordedContract` records (`name`, source name, pack, full schema, normalized execution policy, connector ID, binding revision and authority revision). For A2A use `kind:"a2a"`, `protocol:"a2a-jsonrpc-0.3"`, the same root endpoint `http://allowed.e04.test:8081`, and `allowed_agent_ids` containing only the fixture's registered agent. `build_environment_registry` automatically registers the concrete executor for these two kinds; there is no callback name or dynamically imported class in the JSON. The scoped connector must itself use the exact fixture endpoint and matching current tool policy, without inherited global headers or environment credentials. Binding revisions are the digest of the current connector metadata; they are not arbitrary client revision labels. The metadata integration test demonstrates constructing that digest from the scoped record without decrypting credentials or opening a connection.

An expired running phase is never taken over: its original claim identity is retained with an unknown-outcome marker and the lease is quarantined. Prepare exceptions (including a Docker CLI timeout) retain that uncertainty because terminating the CLI cannot prove the daemon stopped. Cleanup/absence observations do not resolve it. Only a conclusive exact original-attempt completion can remove the marker, after which explicit administrator cleanup and verification may release the lease. A timeout with no conclusive original completion remains quarantined even after removal of all presently observed owned resources.
